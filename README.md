# UniqID-X

UniqID-X is a Go package for 16-byte, time-sortable identifiers. It combines sequential database-friendly IDs, coordinated or offline generation, human typo checks, optional tamper-evident HMAC authentication, and optional AES-GCM confidentiality.

It is not a UUID. Store it as raw 16-byte binary (`BYTEA` or `BINARY(16)`) and always use a database `PRIMARY KEY` or `UNIQUE` constraint.

## What each feature proves

| Need | Feature | What it proves |
|---|---|---|
| Unique coordinated IDs | leased 69-bit generator token + logical clock + sequence | no duplicate within the allocation domain when tokens are never reused |
| Offline IDs | CSPRNG session token | probabilistic uniqueness, not an absolute guarantee |
| Human typing mistakes | Verhoeff / Luhn checksums | only that the text was typed consistently |
| Issuer/tamper verification | HMAC signed token | an issuer holding the secret authenticated this ID and context |
| Hide timestamp/token fields | AES-256-GCM token | confidentiality and tamper detection |

Checksums never prove that an ID was generated by your service. Use a signed HMAC token for that requirement.

## Quick start

```go
ctx := context.Background()
gen, err := uniqidx.NewGenerator(ctx, uniqidx.Config{Mode: uniqidx.ModeOffline})
if err != nil { log.Fatal(err) }
defer gen.Close(ctx)

id, err := gen.Next(ctx)
if err != nil { log.Fatal(err) }
fmt.Println(id.Text()) // UX1V-<26 Base32hex characters>-<check digit>
```

## Full working example

Run the full demonstration:

```sh
go run ./cmd/example
```

It shows:

- Offline and coordinated generation
- Full fields: version, mode, variant, logical time, token, sequence
- Hex, Base32hex, Base64url, text, and numeric representations
- Verhoeff, Luhn, and combined checksum parsing
- Compact HMAC tokens and v1 signed-envelope verification
- AES-256-GCM encryption/decryption
- Lease renewal and `database/sql` raw-byte round trips

The example uses in-memory keys and `lease.NewMemory`, which is process-local and suitable only for examples/tests. It enforces the lease ownership handle for renew/release, but cannot preserve allocation history across process restarts. Production coordinated mode requires a durable, strongly consistent `LeaseProvider` that never reissues tokens. Use a KMS, Vault, HSM, or equivalent secret-management system for keys.

## CLI

The included local CLI supports offline generation and strict inspection/validation:

```sh
go run ./cmd/uniqidx generate
go run ./cmd/uniqidx validate 'UX1V-...'
go run ./cmd/uniqidx inspect 'UX1V-...'
```

It also supports the canonical `ux1s` HMAC envelope. Provide a 32-byte hexadecimal secret through `UNIQIDX_HMAC_KEY`; never pass secrets as command-line arguments.

```sh
export UNIQIDX_HMAC_KEY='0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef'
go run ./cmd/uniqidx sign 'UX1V-...' orders/update
go run ./cmd/uniqidx verify 'ux1s.env....' orders/update
```

## HTTP example

A minimal standard-library HTTP example is included for integration testing:

```sh
go run ./cmd/http
curl -X POST http://localhost:8080/v1/ids
curl 'http://localhost:8080/v1/ids/UX1V-.../validate'
```

It intentionally uses offline mode and does not authenticate callers or persist IDs; it is an API-shape example, not a production service.

## API map

- `NewGenerator` / `Next` — issue IDs in coordinated or offline mode.
- `Config.Variant` — select a two-bit variant without changing the 16-byte ID size.
- `ID.Fields` — inspect version, mode, timestamp, token, and sequence.
- `ID.Text` / `ID.Numeric` — canonical Verhoeff-protected values.
- `TextWith` / `NumericWith` — choose Luhn or combined checksums.
- `ParseText`, `ParseNumeric`, `ParseBase32`, `ParseBase64URL`, `ParseHex` — strict parsers.
- `ValidText` / `ValidNumeric` — simple `true`/`false` checksum and format validation.
- `Sign` / `Verify` — rotatable-key `ux1s` HMAC signed envelope.
- `SignHMAC` / `VerifyHMAC` — legacy compact numeric-key HMAC envelope; prefer `Sign` / `Verify` for new APIs.
- `NewAEADSigner`, `Seal`, `OpenAEAD` — AES-256-GCM confidential envelope.
- `ID.Value` / `ID.Scan` — `database/sql` binary integration.
